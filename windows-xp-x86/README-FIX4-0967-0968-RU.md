# PMLMRIM x86 FIX4 — диагностика создания контактов

На основании журнала FIX3 от 3 ноября 2026 г.: пакет `CONTACT_LIST2` (0x1037) содержит 13 контактов, `parseRoster` возвращает 13 записей, но `EnsureContact` возвращает 0 для каждой. Это объясняет отсутствие списка в базе. По журналу нельзя определить, возвращает ли 0 именно `db_add_contact()` или входные данные некорректны, поскольку FIX3 не логировал внутренности `EnsureContact`.

FIX4 сохраняет обход групп и отключение X-Status extra icons из FIX3. Порядок вызовов создания контактов не меняется. Добавлен узкий журнал `%TEMP%\PMLMRIM-x86-CONTACT-TRACE.txt` для обеих версий SDK. Не записывает email, пароли или тексты сообщений.

Если `email length` равна нулю, виноват разбор/передача адреса из ростера. Если `module length` равна нулю, сломана инициализация аккаунта. Если `Ensure db_add_contact FAILED`, то ошибка именно при создании записи в базе; тогда потребуются отладчик и сведения об используемом SDK. Если `Ensure Proto bind MISMATCH`, необходимо разбираться с привязкой протокола.

Также приложите `%TEMP%\PMLMRIM-x86-FIX-TRACE.txt`, чтобы проверить входящие пакеты. В текущем отчёте для последнего запуска нет доказательства получения пакета входящего сообщения (0x1009).

Собирать `0.96.7` и `0.96.8` отдельно, `Release|Win32`; x64 исходники из другой рабочей версии не заменять. FIX4 — диагностика, а не подтверждённое исправление.
