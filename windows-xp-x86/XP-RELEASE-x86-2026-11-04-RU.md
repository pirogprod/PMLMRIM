# Windows XP SP3 — Release x86 (Visual Studio 2019)

## Назначение

Это **кандидат для тестирования**, а не проверенный стабильный релиз. Основой служит последняя версия исходников x86 с исправлениями контактов, групп и сообщений. Изменены только свойства **Release|Win32** в vcxproj для Miranda NG 0.96.7 и 0.96.8. Исходный код и x64-конфигурации оставлены без изменений.

## Настройки

- v141_xp, WINVER / _WIN32_WINNT 0x0501, подсистема Windows 5.01 (как в исходном проекте).
- **/MD** (обычная Release CRT, не /MDd) — Debug CRT не требуется.
- **/Od** (без оптимизаций компилятора), **/Zi** + PDB, **/GS**.
- Без /GL, без link-time оптимизации, без удаления/слияния COMDAT (/OPT:NOREF /OPT:NOICF).
- Настройки **только для Release | Win32**; x64 не изменяется.

## Как собирать

1. В VS 2019 установите компонент MSVC v141_xp и Windows SDK с XP-совместимым целевым набором.
2. Откройте проект из соответствующей ветки SDK (0.96.7 или 0.96.8). Внешние Miranda SDK / property sheets должны быть от соответствующей версии.
3. Выберите **Release | Win32**, затем **Rebuild**.
4. Проверьте созданный DLL через `dumpbin /headers` (Machine x86, subsystem 5.01) и `dumpbin /dependents` (нет `ucrtbased.dll`, `vcruntime140d.dll`, `msvcp140d.dll`; нет импортов WinAPI только для Vista+).
5. Используйте Release CRT, совместимую с XP: для VC++ 2015–2019 **14.16.x** и подходящую XP-совместимую UCRT (например набор, идущий с целевой Miranda). Само наличие v141_xp НЕ гарантирует, что все внешние зависимости поддерживают XP.
6. Проверяйте загрузку и работу на **Windows XP SP3 x86** и на 32-битной Miranda NG, в том числе на *чистом профиле*, после повторного создания учётки и нескольких подключений.

## Важное предупреждение

Release с /Od может воспроизвести поведение Debug, но **не устраняет undefined behavior, повреждение памяти или ошибки времени жизни объектов**. Прежний DEP-crash PMLICQ остаётся нерасследованным, и это решение не обещает отсутствие вылетов. Сохраните PDB от той же DLL. После очередного падения снимите полный стек и дамп. НИКОГДА не выключайте DEP как способ обхода.

Перед тестами сохраните `profile.dat`, не заменяйте рабочие x64 DLL. Публикуйте как experimental / test candidate, а не stable.
