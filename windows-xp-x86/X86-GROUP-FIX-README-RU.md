# PMLMRIM x86 — GROUP FIX (кандидат для тестирования)

Основа: PMLMRIM-UNIFIED-XP-COMPAT-VS2019-0967-0968-GITHUB.zip. Исходники для Miranda NG 0.96.7 и 0.96.8 лежат в отдельных каталогах.

## Изменено

- Парсер современного MRIM `CONTACT_LIST2` сохраняет имена групп из серверного блока. Ранее имена групп пропускались, поэтому применять ICQ-фикс без изменения парсера было бессмысленно.
- Для каждого контакта выполняется проверка имени группы (Unicode, длина до 128 символов, отсутствие разделителей и управляющих символов).
- Используются `Clist_GroupExists` / `Clist_GroupCreate` / `Clist_ContactChangeGroup` вместо прямой записи `CList/Group` или `Clist_SetGroup`.
- Сохранили прежнюю обработку контактов, статусов, авторизации, сообщений, аватаров и файлового протокола без изменений.
- В Netlib Debug Log записываются этапы `MRIM GROUP_FIX`, включая результат перемещения контакта.
- Для старого `CONTACT_LIST_ACK` пока не декодируются имена групп из фиксированного legacy-блока — существующая локальная группировка сохраняется.

## Важные ограничения

Это экспериментальный **исходный код**, а не проверенный двоичный фикс. Сборка и тест на Windows не проводились. MRIM-сервер может использовать другой способ индексации групп; если контакты оказываются в неверных группах, нужен обезличенный лог и образец протокольных данных (без адресов и переписки). Разрядность проекта установите в `Release | Win32`, `v141_xp` при необходимости XP. Для x64 используйте прежнюю, неизменённую версию исходников.

## Тестирование

1. Сделайте резервную копию portable-профиля и предыдущей DLL.
2. Соберите нужный проект x86 под SDK той же Miranda, запустите под отладчиком.
3. Проверьте вход, количество контактов, соответствие названий групп серверу, получение/отправку сообщений.
4. При вылете пришлите Call Stack и строки `MRIM GROUP_FIX` из Netlib Log; старый `%TEMP%/PMLMRIM-roster.txt` также содержит диагностические счётчики, но не групповые имена.

Данный архив предназначен только для x86 и не изменяет рабочую x64-ветку.
