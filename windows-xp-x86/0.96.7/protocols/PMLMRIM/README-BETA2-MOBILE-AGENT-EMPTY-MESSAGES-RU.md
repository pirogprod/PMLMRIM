# PMLMRIM BETA 2: пустые сообщения в Mobile Agent

Симптом из серверного лога: отправитель PMLMRIM 1.15 отправляет `MESSAGE` с `flags=0x0`; получатель Mobile Agent 1.21 зарегистрирован как `utf16=true`. Сервер делает перекодирование между режимами, но на Mobile Agent сообщение появляется пустым.

Изменение: исходящие обычные сообщения по умолчанию отправляются как UTF-16LE с `MESSAGE_FLAG_UTF16=0x00100000`, в том числе русские. Это позволяет серверу увидеть `sender utf16=true` и не полагаться на конвертацию CP1251 -> UTF-16 в промежуточном звене. Формат пакета: `flags (UL), recipient (LPS), text (LPS байтов UTF-16LE), rtf (пустой LPS)`.

Совместимость: опция DB Editor для аккаунта PMLMRIM `MessageEncoding` (byte): `1` = UTF-16LE (по умолчанию), `0` = старый CP1251 без UTF-16-флага. Эта опция затрагивает только обычные исходящие сообщения, НЕ X-статусы.

Проверка: отправить `Привет` в Mobile Agent и проверить, что сервер пишет `sender utf16=true`, получатель видит полный текст. Проверить отправку после повторного подключения, входящий обмен, ответы/ACK и отправку в старый Jimm. Если Mobile Agent всё ещё показывает пустой текст при sender utf16=true, потребуется захват доставленного сервером MESSAGE_ACK: одних логов исходящей стороны недостаточно.

Проверено: локально собрана утилита тестирования `mrim_wire.cpp` + `mrim_session.cpp` под g++; подтверждён флаг `0x00100000`, двоичные байты русского текста и режим CP1251. Сборка плагина Visual Studio и реальный Mobile Agent не проверялись. BETA 1 не изменена.
