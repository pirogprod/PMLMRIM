# Сборка PMLMRIM — Visual Studio 2019

1. Используйте исходники/SDK Miranda NG той же версии, что выбранный каталог **0.96.7** или **0.96.8**.
2. Интегрируйте проект из `protocols/PMLMRIM/PMLMRIM.vcxproj` в соответствующее дерево Miranda NG с зависимостями, включёнными в её штатный процесс сборки. Самостоятельного полного `.sln` здесь нет.
3. Для Windows XP x86 выберите **Release | Win32**, инструментальный набор **v141_xp**; в данной линии сохранены `/Od`, Release CRT (`/MD`) и отладочные символы при соответствующих настройках проекта. Установите необходимые компоненты VS 2019.
4. Для x64 используйте каталоги `x64/` и штатную x64-конфигурацию, не подменяя заголовки SDK 0.96.7 заголовками 0.96.8 или наоборот.
5. Выполните **Clean** и **Rebuild**; убедитесь, что собранная DLL подходит по разрядности к Miranda32.exe / Miranda64.exe.
6. Проверяйте на копии portable-профиля: первый вход, повторное добавление учётной записи, список/группы, отправка и получение сообщений, X-Status, поиск по e-mail, переключение кодировки.
7. Для XP проверьте импорты DLL, доступность Release CRT и реальную загрузку в Windows XP SP3. `v141_xp` сам по себе не гарантирует, что остальные компоненты Miranda совместимы с XP.

**0.96.8 C2660:** `src/proto.cpp` и `src/server.cpp` должны вызывать `db_add_contact(m_szModuleName, 0)`. Для 0.96.7 применяется API без аргументов и привязка к протоколу. Не заменяйте оба варианта без учёта SDK.

**Поиск:** ошибка интерфейса «не могу запустить поиск» может означать неверный обработчик или флаги возможностей; отсутствие результатов после отправки запроса требует проверки ответа сервера и Netlib Log.

Не распространяйте отладочные CRT-библиотеки как часть обычного Release-дистрибутива. Соблюдайте лицензии исходников/ресурсов, см. корневые документы репозитория.

**DEP hardening (только x86):** перед публикацией проверьте несколько циклов добавления и удаления аккаунта с активным X-Status, отключение и повторное подключение, работу обоих режимов кодировки и сообщения. Для расследования DEP сохраняйте PDB *точно той же* сборки DLL и стек Visual Studio. При повторении вылета выполните сравнительный тест без PMLICQ и с временно отключёнными сторонними хуками.
