# PMLMRIM — протокол Mail.Ru Agent / MRIM для Miranda NG

**Неофициальный экспериментальный плагин PMLMRIM** для Miranda NG. Исходники предназначены для Visual Studio 2019 и требуют соответствующее дерево исходников/SDK Miranda NG. Это **не** официальный клиент Mail.ru/VK.

> **Статус: тестовая версия исходников (5 ноября 2026; x86 DEP hardening).** ZIP содержит исходный код, не готовые бинарные DLL. Последние изменения поиска, переключения кодировок и поддержки 0.96.8 проверялись на уровне исходников; полное тестирование Windows, XP и реального MRIM-сервера для этой ревизии не подтверждено. До замены DLL сохраните предыдущую DLL и резервную копию профиля.

Каждая ветка содержит проект `protocols/PMLMRIM/PMLMRIM.vcxproj`. Проекты предназначены для интеграции в соответствующее дерево Miranda NG; **в архиве нет автономного `.sln`**, а зависимости Miranda необходимо подключить отдельно. Не смешивайте версии SDK и разрядности DLL.

## Возможности

- Подключение к совместимому серверу MRIM, контакт-лист, статусы, обмен сообщениями, авторизация.
- X-Status, иконки, дополнительные сведения о контактах и аватары (зависят от сервера и используемых ресурсов).
- **Тестовый поиск по полному e-mail** из окна поиска Miranda: `SearchByEmail`, `PF1_SEARCHBYEMAIL`, `WP_REQUEST` → `ANKETA_INFO`, тайм-аут/ACK. Результат зависит от поддержки сервера и ещё требует полноценной проверки.
- **Выбор кодировки исходящих сообщений** в настройках учётной записи: `UTF-16LE` (по умолчанию) либо `Windows-1251`. Входящие сообщения обрабатываются автоматически по признакам MRIM. См. `docs/updates/README-MESSAGE-ENCODING-RU.md`.
- Экспериментальная передача файлов; прямой TCP-режим **не означает подтверждённую работу во всех сценариях**, обход NAT / MRIM-прокси не подтверждён.

## Обновление безопасности и устойчивости x86 (DEP LIFECYCLE HARDENING — тест)

- Для **x86 0.96.7 и 0.96.8** обновлён `src/proto.cpp`: синхронизация реестра экземпляров PMLMRIM при обновлении X-Status, дополнительная проверка GUI-окна и изменение порядка исключения экземпляра из реестра при уничтожении.
- Это **устранение потенциального риска использования уже уничтоженного объекта**, а не доказанное исправление конкретного DEP-вылета. В отчёте от 5 ноября 2026 стек не позволил определить виновную функцию или модуль.
- **x64 исходники не изменялись** этим обновлением; поиск по e-mail, настройка кодировки, контакты, сообщения и исправление `db_add_contact()` для 0.96.8 сохранены.
- **Сборка, запуск и отсутствие новых вылетов не подтверждены**. Тестируйте на резервной копии профиля, особенно удаление и повторное создание учётной записи, несколько переподключений, X-Status и сообщения.
- Подробности: [`docs/updates/README-X86-DEP-HARDENING-RU.md`](docs/updates/README-X86-DEP-HARDENING-RU.md).
