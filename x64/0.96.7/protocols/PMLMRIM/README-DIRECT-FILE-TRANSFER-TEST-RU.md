# Тестовая интеграция передачи файлов PMLMRIM

## Что сделано

* В `src/mrim_file_api.cpp` методы Miranda NG `SendFile`, `FileAllow`, `FileDeny`, `FileCancel` привязаны к реальным состояниям файловых сеансов.
* Отправитель открывает TCP-listener на свободном порту, отправляет `MRIM_CS_FILE_TRANSFER` со списком файлов, размерами и локальными IPv4-адресами.
* Входящее предложение передаётся стандартному обработчику файла Miranda NG через `ProtoChainRecvFile` и `DB::FILE_BLOB`. Скачивание не начинается без вызова `FileAllow`.
* Получатель подтверждает `MRIM_CS_FILE_TRANSFER_ACK` (status=1), подключается к указанному адресу и обменивается `MRA_FT_HELLO`, `MRA_FT_GET_FILE`.
* По отдельному TCP-соединению передаются реальные данные файлов; `ACKTYPE_FILE` сообщает о подключении, ходе и результате. Отмена останавливает передачу, отказ отправляет status=0.
* Размеры MRIM ограничены 32-разрядными значениями, пути удалённого пользователя проверяются, уже существующие файлы не перезаписываются. При неполном получении новые файлы удаляются.
* Плагин сообщает `PF1_FILESEND|PF1_FILERECV` (тестовая сборка, не для производственного использования).

## Известные ограничения

* **MRIM-прокси (0x1044–0x1047) пока НЕ реализован.** Код использует прямое TCP. На одном компьютере и в локальной сети соединение потенциально возможно, через NAT/фаервол без проброса порта соединение может не состояться.
* Не реализована передача по резервному соединению отправителя к получателю, если первый прямой канал не удалось создать.
* Работа через Windows DLL и два живых MRIM-клиента не проверена. Нельзя считать интеграцию гарантированно работоспособной без тестовой сборки и проверки.
* На данный момент протокол не поддерживает докачку или переименование существующего файла: целевой файл с тем же именем вызовет ошибку.
* Некоторые версии серверов MRIM могут требовать иного кодирования названий файлов; проверяйте кириллицу отдельно.

## Как проверять

1. Собрать `PMLMRIM.vcxproj` для нужной архитектуры на используемой версии Miranda NG.
2. Начать с двух аккаунтов на одном компьютере либо в одной локальной сети.
3. Отправить небольшой файл ASCII-имени, принять входящую передачу и сравнить полученный файл побайтово.
4. Проверить несколько файлов, отмену, отклонение, существующий файл и разрыв соединения.
5. Только после этого тестировать разные внешние сети; без прокси/NAT-туннелирования будут ограничения.

Старые исправления авторизации, статусов и анкет сохранены. Изменения для передачи файлов: `src/mrim_file_api.cpp` (новый), `src/proto.h`, `src/proto.cpp`, `src/server.cpp`, `PMLMRIM.vcxproj`.
