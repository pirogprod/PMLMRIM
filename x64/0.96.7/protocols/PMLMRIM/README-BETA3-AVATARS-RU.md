# PMLMRIM BETA 3 — аватары (Miranda NG 0.96.8)

Отдельная экспериментальная ветка поверх PMLMRIM BETA 2 UTF-16. Исходный пакет BETA 2 не менялся.

## Новое

- В окне учётной записи и на странице опций добавлены **Avatar server** и **Avatar port**.
- По умолчанию: `obraz.foto.mail.ru`, порт **80** (HTTP).
- Подключён стандартный протокольный Avatar API (`PS_GETAVATARCAPS`, `PS_GETAVATARINFO`).
- Аватары контактов скачиваются отдельным потоком по документированному пути:
  `http://<AvatarServer>:<AvatarPort>/<почтовый-домен без .ru>/<логин>/_mrimavatar`.
  Например: `http://obraz.foto.mail.ru/mail/example/_mrimavatar`.
- HTTP 200, `image/jpeg`, `X-NoImage: 1` (аватар отсутствует), JPEG SOI/EOI, лимит 512 КБ.
- Кэш в `%TEMP%\PMLMRIM-avatars\<имя-учётки>\<хэш-email>.jpg`, с атомарным обновлением.
- Повторная проверка: нет аватара — не чаще раза в 6 часов, имеющийся — обновление через 7 дней.
- Завершение скачивания оповещает AVS через `ACKTYPE_AVATAR`.
- HTTP ограничен таймаутами, ошибка не блокирует Miranda UI.

## Что тестировать

1. Соберите проект под Miranda NG 0.96.8, Win32 либо x64; убедитесь, что установлен плагин Avatar Service (AVS).
2. В настройках PMLMRIM укажите адрес **вашего сервера образов**, если эмулятор использует отдельный адрес, и порт 80 (или свой серверный порт).
3. Откройте аватар контакта. Сервер должен получить GET вида `/mail/username/_mrimavatar`.
4. Если сервер возвращает `X-NoImage: 1`, случайная картинка появляться не должна.
5. Перезапустите Miranda: ранее скачанные JPEG используются из кэша.

## Ограничения

- Проверка при реальном соединении с пользовательским сервером и компиляция MSVC не проводились.
- Отправка/смена **собственной** картинки в BETA 3 не добавлялась: для этого нужен отдельный API загрузки на сервер образов.
- Эта ветка реализует **получение аватаров контактов**. Сервис HTTPS и аутентифицированные запросы не реализованы (документированный оригинальный сервер — HTTP).
- Для неизвестных почтовых доменов используется часть имени домена до первой точки; необходима совместимость сервера образов.
- Изменения в X-статусах и сообщениях не вносились.
