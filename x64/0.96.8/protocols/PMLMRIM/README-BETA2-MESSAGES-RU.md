# PMLMRIM BETA 2 — сообщения и кодировки

Основа: удачная BETA 1 с каталогом Jimm, X-статусами и их описаниями. X-статусы, Extra Icons, меню и Tipper не изменены.

## Анализ приложенных JAR
- Jimm: `aw.class` использует Java `String.getBytes("Windows-1251")` и `new String(bytes, offset, length, "Windows-1251")`. Это подтверждает применение Windows-1251 в одной из строковых функций Jimm, но не доказывает, что *все* сообщения в Jimm передаются исключительно так.
- Jimm: также встречаются UTF-8 и Java `DataInputStream.readUTF`/`writeUTF` — эти функции не следует безусловно переносить на MRIM чат.
- MobileAgent.jar: классы обфусцированы; при статическом поиске не обнаружены явные литералы `Windows-1251`, `UTF-8`, `UTF-16`. Достоверно восстановить его формат отправки сообщений по найденным признакам не удалось.

## Изменения
- Для обычных сообщений сначала используется Windows-1251, как в Jimm и прежнем PMLMRIM.
- Запрещена бесшумная подмена непредставимых символов на `?` в Win32 `WideCharToMultiByte` (`WC_NO_BEST_FIT_CHARS`, `lpUsedDefaultChar`).
- Если сообщение не помещается в CP1251 без потерь, BETA 2 использует UTF-16LE с флагом MRIM `0x00100000`. Это экспериментальная совместимость — принимающая сторона должна поддерживать флаг.
- Приём сообщения по этому флагу уже поддерживался BETA 1 и сохранён.
- При ошибке кодировки сообщение не маркируется как доставленное: остаётся существующий механизм ошибки отправки.

## Проверить на реальных клиентах
1. Русский текст: `Привет, как дела?` (должен идти CP1251).
2. Смешанный текст и emoji: `Привет 🌍` (UTF-16LE и специальный флаг, если принимающий клиент умеет).
3. Английский, цифры, переносы строк.
4. Подтверждение доставки `MESSAGE_STATUS`, отсутствие дублей и входящие UTF-16 сообщения.

ВНИМАНИЕ: В архиве исходники, без проверки сборкой MSVC и без тестов с реальным сервером. Экспериментальный UTF-16 режим может быть несовместим со старыми версиями Mobile Agent. Для максимально старой совместимости используйте символы Windows-1251.
